## 2026-10-17 保存数据被覆盖问题

### 问题

第一次运行保存的学生信息，在第二次运行时再次保存会被覆盖掉，旧数据丢失。

### 原因

`execute()` 里用 `len(self.stu_list) == 0` 来判断"是否需要从文件加载数据"。但 `stu_list` 每次启动都会被 `__init__` 重置为空列表，所以这个条件**永远成立**，`load_student()` 永远不会被执行——旧数据根本没读回内存。而 `save_student()` 用 `'w'` 模式打开文件，会先清空再写入，写进去的只有内存里当前的学生，旧数据自然就没了。

### 解决

把判断对象从"内存列表是否为空"改为"**文件是否存在且有内容**"：

```python
if os.path.exists('./stu_data.txt') and os.path.getsize('./stu_data.txt') > 0:
    self.load_student()
```

### 验证

启动程序后旧数据能正常读回，保存时写入"旧数据 + 新增"，不再互相覆盖。

### 用到的工具/知识点

- `os` 模块（`os.path.exists` / `os.path.getsize`）
- 文件读写模式 `'w'` 的特性

## 2026-10-17 eval() 安全隐患（差点删掉项目）

### 问题

`load_student()` 用 `eval(stu_data)` 解析文件内容。`eval` 会把字符串**当 Python 代码执行**。我在数据文件里写入一行删除命令做验证，运行时程序真的执行了它，Windows 弹出删除确认框——如果路径不是乱码，项目可能就被删了。

### 原因

`eval()` 不区分"数据"和"代码"，文件里的任何内容都会被当作代码执行，存在代码注入风险。

### 解决

改用 `json` 模块：`json.dumps()` 序列化写入、`json.loads()` 解析读取。`json.loads` 只认数据格式，遇到非数据内容会直接报错，绝不当代码执行。

### 验证

写入恶意代码测试，`json.loads` 抛 `JSONDecodeError` 拒绝执行，安全通过。

### 用到的工具/知识点

- `json` 模块（`dumps` / `loads`，`ensure_ascii=False` 支持中文）
- 代码注入风险概念

## 2026-10-17 输入非法值导致程序崩溃

### 问题

添加学生时年龄输入非数字（如 `abc`），`int(input())` 直接抛异常导致程序崩溃；性别、电话也可以随意填，数据质量没保证。

### 解决

抽出一个通用校验函数 `input_check`，通过 `lambda` 传入校验规则，添加和修改共用：

```python
def input_check(self, tip, check_func, error_msg):
    while True:
        value = input(tip).strip()
        if check_func(value):
            return value
        print(error_msg)
```

各字段规则：姓名非空、性别限「男/女」、年龄 1~150、电话 11 位纯数字。用 `str.isdigit()` 先挡非数字，`int()` 转换就不会崩。

### 验证

逐项模拟非法输入（空姓名、性别"x"、年龄 200、电话 123），全部被拦截并提示重输。

### 用到的工具/知识点

- `lambda` 匿名函数
- `str.isdigit()`、`str.strip()`
- 通用函数设计（避免重复代码）

## 2026-10-18 打包成独立可执行文件

### 问题

项目只能在装了 Python 的环境里用命令行运行，发给别人不方便。

### 解决

用 PyInstaller 打包成单个 exe：

```bash
pip install pyinstaller
pyinstaller -F main.py
```

成品 `dist/main.exe` 双击即可运行，无需安装 Python（解释器已捆绑进 exe）。打包生成的 `build/` 和 `.spec` 是中间产物，已清理。

### 验证

模拟操作测试 exe：正常显示菜单、读取数据文件、查询、退出，全流程通过。

### 用到的工具/知识点

- PyInstaller（`-F` 单文件模式）
- 打包原理：代码 + 解释器 + 依赖捆绑

## 2026-10-24 Excel 导入导出功能

### 问题

需要支持从 Excel 批量导入学生信息、把学生信息导出为 Excel（openpyxl 是后端常用库）。

### 踩坑 1：路径校验不完整

程序只检查了 `os.path.exists(路径)`，没有检查"路径是不是 .xlsx 文件"。使用中把**文件夹路径**当成文件路径输入，`load_workbook(文件夹)` 直接崩溃报错。

### 踩坑 2：第三方库装错解释器

用命令行 `pip install openpyxl` 装到了沙箱环境的 Python，而 PyCharm 项目用的是另一个 Python 3.11（`D:\python\python.exe`），导致 PyCharm 里 `import openpyxl` 报找不到模块。第三方库**装到哪个解释器，只有那个解释器能用**，必须确认目标解释器。

### 解决

1. 导出：`Workbook()` 新建工作簿 → `ws.append()` 写表头和数据 → `wb.save('students.xlsx')`。
2. 导入：`load_workbook()` 打开文件 → `ws.iter_rows(min_row=2, values_only=True)` 从第 2 行逐行读取 → 每行按"姓名非空 / 去重 / 性别 / 年龄 / 电话"规则校验，不合规跳过并计数。
3. 补强路径校验：`os.path.isfile()` + `.endswith('.xlsx')` 双重检查，`load_workbook` 用 `try/except` 兜底，非法输入给出友好提示而不是崩溃。
4. 用 `D:\python\python.exe -m pip install openpyxl` 把库装到 PyCharm 的解释器。

### 验证

- 导出 2 条学生 → 生成 xlsx，表头 + 数据完整
- 导入正常行成功，重复 / 空姓名 / 性别非法 / 电话位数错 均被跳过（新增 1 跳过 4）
- 输入文件夹路径、不存在的路径、非 xlsx 文件 → 均给出友好提示，不再崩溃

### 用到的工具/知识点

- `openpyxl`（`Workbook` / `load_workbook` / `append` / `iter_rows`）
- 第三方库安装与解释器匹配（`pip install` 装给谁要明确）
- `os.path.isfile`、字符串 `.endswith()` 路径校验
- `try/except` 异常兜底
